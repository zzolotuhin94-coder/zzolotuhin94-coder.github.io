# DAHUAM.202 Küche — подключение облака (Этап 2)

После подключения кухня, бар и офис работают с одними данными на всех устройствах: меню, техкарты, склад, фото, заказы. Заказы уходят поставщикам письмом одной кнопкой, с вашего адреса.

Без облака приложение тоже работает полностью, но данные хранятся только в одном браузере.

**Что понадобится:** около часа времени, доступ к настройкам домена `dahuam202.at` (DNS) и банковская карта, если выберете платный тариф.

**Стоимость (проверьте актуальные цены на сайтах):**
- **Supabase.** Бесплатный тариф подходит, чтобы попробовать, но останавливается после 7 дней без активности. Для работы ресторана нужен тариф Pro, около 25 $ в месяц.
- **Brevo** (почтовый сервис из ЕС). Бесплатно до 300 писем в день, для заказов этого хватает с запасом.

## Шаг 1. Проект в Supabase
1. Зарегистрируйтесь на https://supabase.com и нажмите **New project**.
2. **Region: Frankfurt (eu-central-1)**, чтобы данные оставались в ЕС (требование GDPR).
3. Сохраните пароль базы данных в надёжном месте.

## Шаг 2. Создать таблицы
1. Откройте в проекте **SQL Editor**, затем **New query**.
2. Скопируйте туда весь файл `schema.sql` из этой папки и нажмите **Run**.
3. Если появятся сообщения `NOTICE … does not exist, skipping`, это нормально. Файл можно запускать повторно.

Схема включает защиту на уровне строк (Row Level Security): каждый аккаунт видит только данные своего ресторана.

## Шаг 3. Закрыть свободную регистрацию
В разделе **Authentication → Sign In / Providers** выключите **Allow new users to sign up**. Тогда аккаунты сотрудникам создаёте только вы.

## Шаг 4. Аккаунт владельца и ресторан
1. В разделе **Authentication → Users** нажмите **Add user → Create new user**. Укажите e-mail и пароль и поставьте галочку **Auto Confirm User**.
2. В **SQL Editor** выполните, подставив свой e-mail и имя:

```sql
with r as (insert into public.restaurants (name) values ('DAHUAM.202 Restobar | Café') returning id)
insert into public.members (restaurant_id, user_id, name, role)
select r.id, u.id, 'Anna', 'owner' from r, auth.users u where u.email = 'anna@dahuam202.at';
```

## Шаг 5. Сотрудники
Для каждого сотрудника:
1. Создайте пользователя так же, как в шаге 4.
2. Выполните:

```sql
insert into public.members (restaurant_id, user_id, name, role)
select r.id, u.id, 'Bernd', 'chef'
from public.restaurants r, auth.users u
where r.name = 'DAHUAM.202 Restobar | Café' and u.email = 'bernd@dahuam202.at';
```

Роли:

| Роль | В приложении | Что можно |
|---|---|---|
| `owner` | Inhaber | всё, в том числе подтверждать заказы выше лимита |
| `chef` | Küchenchef | заказывать продукты, кроме напитков и вина, в пределах лимита |
| `bar` | Bar | заказывать напитки и вино в пределах лимита |
| `staff` | Mitarbeiter | готовить заказы и принимать товар, отправлять заказы нельзя |

Если сотрудник уволился, удалите его в **Authentication → Users**. Его доступ закроется сразу.

## Шаг 6. Подключить приложение
1. В Supabase откройте **Project Settings → API** и скопируйте **Project URL** и ключ **anon public**.

   Ключ `anon` публичный по замыслу Supabase, его можно вводить в приложение: данные защищены правилами доступа из шага 2. Ключ **service_role** не вводите в приложение и никому не передавайте.
2. В приложении откройте **Einstellungen → Cloud & Team** и введите Projekt-URL, anon key, свой e-mail и пароль. Нажмите **Verbinden**.
3. Первое устройство загружает свои данные в облако. Следующие устройства при подключении спрашивают, что делать. Выбирайте **«Cloud-Daten auf dieses Gerät laden»**.

Облако работает в версии приложения на сайте (`…github.io/dahuam/`). В предпросмотре внутри Claude оно отключено.

## Шаг 7. Отправка заказов письмом
1. **Brevo.** Зарегистрируйтесь на https://www.brevo.com.
2. **Домен.** В разделе **Senders, Domains & Dedicated IPs → Domains** добавьте домен `dahuam202.at`. Внесите записи, которые покажет Brevo (SPF, DKIM, DMARC), в DNS у вашего хостинг-провайдера. Без этих записей письма будут попадать в спам.
3. **Ключ.** В разделе **SMTP & API → API Keys** создайте ключ.
4. **Функция.** В Supabase откройте **Edge Functions → Deploy a new function → Via Editor**. Название — `send-order`, содержимое — файл `functions/send-order/index.ts`. Нажмите **Deploy**.

   Если установлен Supabase CLI, можно и так: `supabase functions deploy send-order`.
5. **Секреты.** В разделе **Edge Functions → Secrets** добавьте:
   - `BREVO_API_KEY` — ключ из Brevo;
   - `ORDER_FROM_EMAIL` — например `bestellung@dahuam202.at` (адрес на подтверждённом домене);
   - `ALLOWED_ORIGIN` — `https://zzolotuhin94-coder.github.io`.

   Вместо Brevo можно использовать Resend: тогда задайте секрет `RESEND_API_KEY`.

После этого в заказе поставщику с e-mail появится кнопка **«Jetzt per E-Mail senden»**. Каждая отправка записывается в таблицу `order_mail_log`. Ответ поставщика приходит на адрес из **Einstellungen → Einkauf → Antwort-E-Mail**.

## Резервные копии и восстановление
- **История версий.** В таблице `kitchen_state_history` хранится не больше одной копии в час за последние 2 дня и одна копия на каждый день за 60 дней. Владелец видит её в **Table Editor**.
- **Откат на старую версию.** Скопируйте поле `data` нужной записи и импортируйте его в приложении через **Einstellungen → Sicherung laden**.
- **Своя копия.** Кнопка «Sicherung erstellen» в приложении работает и с облаком.
