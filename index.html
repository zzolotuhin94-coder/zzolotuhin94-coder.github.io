The problem

A resort village runs on dozens of small businesses — hotels, restaurants, ski lifts, taxis, event organisers — each with its own website, phone line and paper reservation book. Guests don't know what's open today, which lift is running or where there's a free table at 8 pm. Venues lose bookings to phone tag.

The solution

One platform with four parts that talk to each other in real time. A guest books a table in the app → it appears instantly on the restaurant's floor plan → the host accepts it → the guest gets a push notification. A lift opens in the morning → every guest who asked for it is notified.

Four parts, one system

Gerlos Life — guest app

React Native · Expo · offline-first

  • Hotels, restaurants, ski-lift status, weather, events and a map
  • Table booking with live availability and reviews
  • “Fabi”, an AI concierge powered by Claude that knows the resort
  • German, Dutch and English, switched instantly
  • Offline cache — the app is never empty, even in a gondola
  • Day / night theme that follows the Alpine sunrise and dusk

AlpenGO Business — partner app

React Native · Zustand · Reanimated

  • Reservations and waitlist with accept / decline in one tap
  • Interactive floor-plan editor — drag tables, see live occupancy
  • Reservation timeline for the whole evening
  • Menu builder, events, venue photos
  • Analytics and review moderation
  • Hotel module: rooms, housekeeping, occupancy calendar
  • Adapts to the business type — restaurant, hotel, taxi or activity

Super-admin console

Resort-wide control

  • Onboard businesses with invite keys, per-business modules
  • Subscriptions and billing
  • Broadcast messages to every guest
  • QR attribution — which poster brought which guest
  • Audit log, system health, backups

Backend API

Node.js · Express · PostgreSQL

  • JWT auth with rate limiting and Helmet
  • Socket.io rooms for instant updates
  • Reservation state machine with overbooking checks
  • Stripe billing, Sentry monitoring, schedulers
  • Expo push notifications, 28 versioned migrations

How it fits together

Engineering highlights

01

Real-time from tap to table

A booking travels guest app → API → PostgreSQL → Socket.io → partner app in well under a second. The host's floor plan lights up, the guest sees confirmed without refreshing.

02

A reservation state machine

Six states — pending, confirmed, rejected, arrived, completed, cancelled — with explicit allowed transitions, time windows and capacity checks, so a table can't be double-booked for the same slot.

03

AI concierge that knows the valley

Guests ask “where can we eat with kids tonight?” in their own language. The concierge answers from resort data through the Claude API, and conversations are stored and archived on the server.

04

Drag-and-drop floor plans

Restaurants draw their own room: tables are dragged, resized and numbered on a canvas built with Reanimated and gesture handlers, then used for live occupancy during service.

05

Offline-first by design

Mountains have dead zones. Data is fetched fresh, cached locally and served from cache when the network drops — with bundled data as a last resort, the app is never blank.

06

Built to be operated

Helmet, JWT and rate limiting on the API, Sentry for errors, audit logging of admin actions, scheduled jobs, backups and a system-health view for the resort team.
